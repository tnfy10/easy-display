# Easy Display

모니터마다 해상도, HiDPI 배율, 주사율을 조절하는 macOS 앱입니다. 내부 렌더링 해상도와 **모니터로 나가는 실제 출력 신호**를 구분해서 보여 줍니다.

## 주요 기능

- 연결된 모니터별 해상도 및 지원 주사율 선택
- HiDPI / 일반 배율(LoDPI) 모드 구분
- UI 크기, 내부 렌더링 크기, 실제 출력 신호 동시 표시
- **15초 변경 미리보기**: 확인하지 않으면 이전 설정으로 복구
- 별도 복구 프로세스: 앱이 종료되거나 응답하지 않아도 20초 뒤 미확인 변경 복구 시도
- 사용자 지정 HiDPI 해상도 등록: 관리자 인증 후 모니터 모델 전용 override 파일 저장
- 기존 설정 백업, 중복 없이 모드 추가, 등록 전 설정 복원
- 여러 모니터 배치: 확장/미러링 전환, 미러링 원본 선택, 주 모니터 지정, 끌어서 위치 정렬
- HDR 지원 모니터의 HDR 켜기/끄기
- 색 출력 형식 선택: RGB Full / Limited 범위, YCbCr 4:4:4·4:2:2·4:2:0, 비트 심도
- 모니터 화면 방향 전환: 가로 / 세로(90°·270°) / 180° 회전, 15초 미리보기 후 유지
- GitHub 릴리스 기반 앱 내 자동 업데이트
- 메뉴 막대에서 앱 열기, 모니터 선택, 미러링/확장 전환
- 진단 정보 클립보드 복사, 밝은/어두운 시스템 테마 지원

일반적인 해상도 변경에는 관리자 권한이 필요하지 않습니다. 새 HiDPI 모드를 등록하거나 등록 전 파일을 복원할 때만 macOS 관리자 인증이 필요합니다. 별도 유료 앱, 화면 기록 권한, 접근성 권한은 사용하지 않습니다.

## 다운로드

[Releases](https://github.com/tnfy10/easy-display/releases/latest)에서 `Easy-Display-<버전>.zip`을 받아 압축을 풀고 `Easy Display.app`을 응용 프로그램 폴더로 옮기세요. `v*` 태그를 푸시하면 GitHub Actions가 테스트, 빌드, 릴리스 게시를 자동으로 진행합니다.

## 실행

macOS 14 이상, Swift 6 / Xcode 16 이상이 필요합니다. Apple Silicon에서 개발 및 검증했습니다. Intel용 빌드는 해당 아키텍처에서 별도 검증이 필요합니다.

```sh
git clone https://github.com/tnfy10/easy-display.git
cd easy-display
bash scripts/build.sh
open 'build/Easy Display.app'
```

빌드된 앱은 `build/Easy Display.app`에 있습니다. 로컬 개발용 ad-hoc 서명이 적용됩니다. Apple Developer ID 서명과 공증은 포함되지 않습니다. 다운로드한 빌드가 차단되면 시스템 설정의 정상 승인 절차를 사용하세요.

## 해상도 조절

1. 왼쪽에서 모니터를 선택합니다.
2. 화면 크기와 주사율을 선택합니다. 기본 목록에는 HiDPI와 현재 사용 중인 모드가 표시됩니다.
3. **설정 적용**을 누르면 선택한 설정으로 화면이 즉시 바뀝니다.
4. 적용 후 15초 안에 글자 크기, 모니터 경고 및 실제 출력 신호를 확인합니다.
5. **이 설정 유지**를 누르면 macOS에 영구 설정을 저장합니다. 복구를 누르거나 15초가 지나면 이전 설정으로 돌아갑니다.

예를 들어 QHD 모니터의 `1920×1080 HiDPI`는 내부적으로 `3840×2160`으로 그리면서 실제 신호는 `2560×1440`일 수 있습니다. 반대로 어떤 모드는 실제 신호도 4K로 바꿀 수 있습니다. 이 앱은 두 값을 별도로 표시하며, 미리보기 전후 신호 해상도가 달라지면 안내합니다. **모니터 경고가 보이면 유지하지 말고 복구하세요.**

주사율은 macOS가 해당 모드에 대해 제공하는 목록에서 선택합니다. 임의의 타이밍을 강제로 생성하거나 하드웨어 한계를 해제하지 않습니다. 미러링 중인 디스플레이는 해상도 변경을 막습니다.

## 여러 모니터 배치

모니터가 두 대 이상 연결되면 **여러 모니터 배치** 카드가 표시됩니다.

- **확장 / 미러링**: 모든 모니터를 확장 화면으로 쓰거나, 선택한 모니터(없으면 주 모니터) 화면을 모든 모니터에 미러링합니다. 메뉴 막대 아이콘에서도 전환할 수 있습니다.
- **이 모니터에 표시할 화면**: 모니터별로 독립 화면(확장)으로 쓰거나 다른 모니터를 미러링하도록 지정합니다. 세 대 이상이면 일부만 미러링할 수 있습니다.
- **주 모니터로 설정**: 메뉴 막대와 Dock이 표시될 모니터를 바꿉니다. 미러링된 모니터는 주 모니터가 될 수 없습니다.
- **정렬**: 배치 화면에서 모니터를 끌어 놓으면 가장 가까운 다른 모니터의 가장자리에 붙습니다. 위·아래·가운데 정렬 근처에서는 자동으로 맞춰집니다. 위쪽 막대가 있는 모니터가 주 모니터입니다.

세 대 이상이면 **고급: 일부 모니터만 미러링**에서 모니터마다 독립 화면 또는 다른 모니터 복제를 고를 수 있습니다.

위치와 주 모니터 변경은 출력 신호를 바꾸지 않으므로 바로 저장됩니다. 미러링/확장 전환은 해상도와 신호가 바뀔 수 있어 해상도 변경과 같이 **15초 확인** 후 유지하며, 확인하지 않으면 별도 복구 프로세스가 이전 배치(미러링 구성, 위치, 해상도)로 되돌립니다.

## HDR

HDR을 지원하는 모니터에는 **HDR** 스위치가 표시됩니다. macOS 시스템 설정과 같은 내부 기능(SkyLight 비공개 API)으로 전환하며, 이 기능이 없는 macOS 버전에서는 스위치가 숨겨집니다. 전환 후 15초 안에 유지를 누르지 않으면 별도 복구 프로세스가 이전 상태로 되돌립니다. 미러링된 모니터는 원본 모니터에서 설정하세요. 케이블, 도크, 모니터 입력 설정에 따라 HDR이 켜지지 않을 수 있습니다.

## 색 출력 형식 (RGB Full / Limited)

외장 모니터마다 **색 출력 형식** 카드가 표시됩니다. 카드 위쪽에 지금 케이블로 나가는 신호 형식(예: `YCbCr 4:4:4 · Limited · 8비트`)이 표시됩니다.

- **RGB 범위**: `Full (0–255)`은 PC 모니터, `Limited (16–235)`는 TV·영상 장비의 표준입니다. macOS가 HDMI TV나 일부 모니터를 TV로 인식해 YCbCr/Limited로 출력하면 검은색이 회색처럼 뜨고 색이 바래 보이는데, 이때 **Full**을 고르면 됩니다. 반대로 어두운 부분이 뭉개지면 Limited를 고르거나 모니터의 입력 범위(블랙 레벨) 설정과 맞추세요. 현재 비트 심도를 유지할 수 있으면 유지합니다.
- **세부 형식**: 모니터와 현재 해상도·주사율에서 macOS가 허용하는 형식(RGB / YCbCr 4:4:4·4:2:2·4:2:0, 8·10·12비트)만 표시됩니다. HDR이 켜져 있으면 HDR 형식만, 꺼져 있으면 SDR 형식만 보입니다.

macOS 내부 기능(SkyLight 비공개 API)으로 바꾸며 관리자 권한이 필요하지 않습니다. 고르는 즉시 바뀌고, 15초 안에 유지를 누르지 않으면 별도 복구 프로세스가 이전 형식으로 되돌립니다. 유지한 설정은 macOS가 모니터별로 저장합니다. 해상도나 주사율을 바꾸면 macOS가 형식을 다시 고를 수 있으니 다시 확인하세요. 이 기능이 없는 macOS 버전이나 형식을 하나만 지원하는 모니터에서는 카드가 숨겨집니다.

## 업데이트

앱은 실행 시와 6시간마다 [GitHub Releases](https://github.com/tnfy10/easy-display/releases)의 최신 버전을 확인합니다. 새 버전이 있으면 내려받아 체크섬, 번들 ID, 버전, 코드 서명을 검사한 뒤 앱을 교체하고 다시 실행합니다. 진행 중인 화면 설정 확인이 있으면 설치를 미룹니다.

- 설정(⌘,)에서 자동 확인과 자동 설치를 끌 수 있습니다. 메뉴 막대와 앱 메뉴의 **업데이트 확인…**으로 직접 확인할 수도 있습니다.
- 앱이 응용 프로그램 폴더처럼 쓰기 가능한 위치에 있어야 자동으로 교체됩니다. 그렇지 않으면 릴리스 페이지를 엽니다.
- 업데이트 확인은 GitHub API를 로그인 없이 호출하므로 **저장소가 공개 상태여야** 동작합니다.

## 사용자 지정 HiDPI 모드

**모드 추가…**에서 다음처럼 입력합니다.

```text
1920x1080, 2048x1152, 1680x945
```

- 쉼표, 줄바꿈, 세미콜론 구분. `×`도 지원합니다.
- 1~24개, 가로 640~3840 / 세로 360~2160. 현재 신호를 읽을 수 있으면 화면 비율도 검사합니다.
- 물리 출력 타이밍이 아니라 HiDPI 렌더링 모드를 추가하도록 요청합니다.
- **등록 후 직접 재시동해야 합니다.** 재시동 뒤 실제 지원 모드 목록에서 선택하세요.
- 모드는 제조사·모델 단위로 적용됩니다. 같은 모델 모니터에는 함께 적용될 수 있습니다.
- 내장 디스플레이에는 사용자 지정 등록을 제공하지 않습니다.
- macOS, 케이블, 도크, GPU, 모니터에 따라 요청한 모드가 무시되거나 일부 주사율만 제공될 수 있습니다. 현재 해상도와 정확히 같은 HiDPI 모드도 항상 제공되지는 않습니다.
- DisplayLink처럼 다른 드라이버가 관리하는 화면에서는 override가 반영되지 않을 수 있습니다.

시스템 파일 위치:

```text
/Library/Displays/Contents/Resources/Overrides/
  DisplayVendorID-<vendor>/DisplayProductID-<product>
```

앱은 해당 모델의 **파일 한 개만** 수정합니다. 기존 plist 키와 해상도 항목은 보존합니다. EDID를 바꾸거나 SIP를 해제하거나 시스템 전역 배율을 강제로 켜지 않습니다. 관리자 인증을 취소하면 파일이 변경되지 않습니다.

백업 위치:

```text
~/Library/Application Support/EasyDisplay/override-<vendor>-<product>.json
```

여러 번 모드를 추가해도 첫 등록 전 원본을 유지합니다. **등록 전 설정 복원…**을 누르면 원본 파일을 되돌립니다. 처음에 파일이 없었다면 앱이 만든 파일만 제거합니다. 다른 도구가 파일을 변경한 경우에는 덮어쓰지 않고 중단합니다. 복원 후에도 재시동이 필요합니다. 앱을 삭제하기 전에 원치 않는 사용자 지정 설정을 먼저 복원하세요.

## 복구 동작과 한계

미리보기는 로그인 세션에만 먼저 적용하며, 유지 버튼을 누를 때 영구 저장합니다. 복구 프로세스는 모니터 UUID로 대상을 식별합니다. 모니터가 분리된 경우 최대 5분 동안 재연결 및 복구를 시도합니다. 앱을 강제 종료해도 복구 프로세스는 계속 실행됩니다. 사용자가 복구 프로세스까지 종료하거나 컴퓨터를 종료하면 이 동작을 보장할 수 없습니다.

실제 출력 신호는 IOKit의 현재 디스플레이 타이밍에서 읽습니다. 이 속성들은 macOS 버전 및 드라이버에 따라 없을 수 있습니다. 확인할 수 없는 환경에서는 **확인 불가**로 표시하며, 내부 렌더링 크기를 실제 신호라고 표시하지 않습니다.

## 개발 및 검증

```sh
swift test
swift run EasyDisplay --diagnose
bash scripts/build.sh
```

테스트는 해상도 입력 검사, 바이트 순서와 HiDPI 플래그, 기존 plist 보존, 중복 제거, 원본 없는 상태의 반복 등록·복원, 모델별 파일 범위, 잘못된 설정 거부 등을 검증합니다. 테스트 실행 자체는 모니터 설정이나 시스템 파일을 바꾸지 않습니다.

GitHub Actions는 `main` 푸시와 PR에서 테스트, 앱 빌드, 코드 서명 및 ZIP 무결성 검사를 실행합니다. 태그 푸시만으로 같은 검증을 중복 실행하지 않습니다. 외부 Swift 패키지 의존성은 없습니다.

앱 ZIP을 다운로드하려면 Actions → macOS → **Run workflow**에서 `upload_artifact`를 켜고 실행합니다. 업로드 파일은 1일 보관합니다. 이 옵션은 기본으로 꺼져 있어 계정의 아티팩트 저장 공간이 가득 차더라도 일반 CI 검증은 동작합니다. 업로드를 명시적으로 선택한 실행에서는 업로드 실패도 그대로 실패로 표시합니다. 계정 저장 한도가 초과된 경우 공간 확보 또는 한도 조정 후 사용해야 합니다.

## 구현 참고

- 일반 모드 변경: CoreGraphics 디스플레이 구성 API
- HiDPI 모드 등록: 모델별 `scale-resolutions` override
- 신호 확인: IOKit의 현재 물리 타이밍. 지원되지 않으면 비워 둠
- 색 출력 형식: SkyLight의 디스플레이 출력 모드(link description) API
- UI: SwiftUI + AppKit

Apple 공식 API 문서: [CGCompleteDisplayConfiguration](https://developer.apple.com/documentation/coregraphics/cgcompletedisplayconfiguration(_:_:)). 모델별 override 형식 참고: [one-key-hidpi](https://github.com/xzhih/one-key-hidpi). 이 프로젝트는 별도로 작성한 구현이며 BetterDisplay 코드나 바이너리를 포함하지 않습니다.
